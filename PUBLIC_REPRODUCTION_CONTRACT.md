# Public reproduction claim contract

This document governs explanatory/public-release review. It has no candidate,
membership, numerical-gate or fidelity authority. It is frozen in the S2 execution
source/input lock **before DEVELOPMENT is opened**.

| Layer | Meaning | Release treatment |
|---|---|---|
| R-A | Independent execution from declared, publicly obtainable inputs | Required; report engineering migrations and input availability |
| R-B | Reproduction of the frozen scientific protocol | Required; no post-hoc tuning |
| R-C | Reproduction of the claim-bearing scientific conclusion | Required; external post-computation adjudication |
| R-D | Exact numerical/artifact identity | Optional; report differences honestly, without invented tolerance |

The published core claim is constructive feasibility in the declared finite-local
regime, not exact survivor counts, universal reliability, or arbitrary-coefficient
finite-AST universality. S1 acceptance includes two documented live engineering
repairs; it is not a one-shot execution from the final source commit.

same AST, same theta and deterministic gauge with zero refit. The 89 unresolved
S1 branches remain REFERENCE, not S2 candidates. The 2438 exact execution classes
may share execution only and never narrow scientific membership.

1. A nonempty DEVELOPMENT operator-PASS cohort exists.
2. The frozen control-first absolute response gate is discriminative: identity and
   frozen NULL controls do not trivially pass, with sufficient numerical evidence.

   operator-PASS cohort is certified on all 32 committed response cases.

External post-computation review will adjudicate `CLAIM_COMPATIBLE`,
`CLAIM_CONTRADICTED`, or `UNRESOLVED`. These conditions do **not** automatically
assign R-C PASS. A valid completed fresh run contradicting the claim blocks public
scientific-release readiness; never change the protocol to force agreement.

Release blockers include zero operator PASS, a nondiscriminative response gate,
zero response PASS after a valid complete campaign, leakage/refit/ranking or altered
gates, and unresolved numerical/fidelity evidence preventing a claim-level decision.
Implementation failures are engineering blockers, not scientific FAIL results.

statistics, never targets. Different PASS fractions, nonzero candidate response
FAILs, or different candidate identities do not alone contradict feasibility. Report
them descriptively and distinguish historical-instance statistics from reproducible
claim-level conclusions in manuscript wording.

clearly worse than identity, with G33/G65 `tau_num=0.005` ambiguity semantics only.
Response radius remains `|E_fine-E_coarse| + u_reference`; PASS requires all 32
upper bounds strictly below 0.15; FAIL requires any lower bound strictly above
0.15; otherwise retain UNRESOLVED. References refine independently of candidates;
candidate escalation is cohort-wide, without candidate-specific rescue.

Full final public readiness still requires S3 reproduction of the SEALED claim.
S2 never opens SEALED. Public input availability/licensing is a separate release
gate: see [PUBLIC_INPUTS.md](PUBLIC_INPUTS.md). Historical replay is reproduction
of already-opened/frozen evidence, not a new sealed-holdout validation.
